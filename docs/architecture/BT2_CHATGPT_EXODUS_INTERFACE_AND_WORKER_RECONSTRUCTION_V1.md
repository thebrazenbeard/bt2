## Runtime reconstruction rule

A fresh BT2 runtime must reconstruct a worker from durable state, not from remembered conversation behavior.

Minimum recovery order:

1. Read current installed BT2 Project Instructions.
2. Fresh-read canonical thebrazenbeard/bt2 source and current exact work subjects.
3. Resolve logical worker role/topology from canonical BT2 source.
4. Resolve the durable communication lane from thebrazenbeard/chat-communication-bus.
5. Read the latest applicable durable assignment/checkpoint/review request.
6. Refresh mutable branch/PR/head/review/provider evidence.
7. Execute only within current authority.
8. Persist work back to source, PR/issue, checkpoint, qualification record, or Bus before treating it as durable.

If a project-specific or future worker has no durable standing role contract, a bounded dispatch must define its role, scope, authority, evidence-refresh requirements, and durable output location. Otherwise the runtime fails closed.
