## DOCUMENTED source framing

The README describes DeltaGNN as a graph neural network with Information Flow Control and an interaction-decoupling mechanism. Reproducibility examples expose flow/topology controls such as graph-density settings and topological measures.

The transfer value for HC is not the specific classifier architecture. It is the concrete existence of a model whose effective computational graph is changed during processing according to state-dependent scores.

## OBSERVED state-dependent edge filtering

In `DeltaGNN.forward_single`, each layer computes a pre-transform aggregation:

```text
prev_x = x
next_x = adj @ x
```

When `flow_flag` is enabled, it then computes node-level delta scores from the difference between the aggregate and prior features, derives first/second-order score terms across layers, and calls `filter_edges`.

`filter_edges` computes each edge score as the mean of its endpoint scores, sorts edges by score, keeps a configured density fraction, and creates a new sparse adjacency used by subsequent processing.

Therefore the effective message-passing topology during one forward computation can differ from the supplied adjacency and can change across layers.

This is a concrete computational example of:

`INPUT_GRAPH != LAYER_EFFECTIVE_GRAPH`

`FORWARD_LOCAL_EDGE_FILTER != STRUCTURAL_EDGE_REMOVAL`

`EPHEMERAL_EFFECTIVE_TOPOLOGY != DURABLE_LOGICAL_TOPOLOGY`

`COMPUTATIONAL_ROUTE_SCORE != WORLD_RELATION_EVIDENCE`

## OBSERVED generated second reasoning graph

When flow control is active, `DeltaGNN.forward` derives aggregate node scores from the first processing path and calls `generate_heterophily_graph`.

That function:

1. obtains connected components from the supplied adjacency;
2. selects one maximum-score node from each retained component;
3. creates pairwise links among those selected nodes;
4. adds self-loop pairs;
5. creates a second sparse graph used by a separate transform path;
6. concatenates the two transformed representations before final output.

The generated graph is therefore an internal computational construction conditioned on current activations/scores. Its existence does not establish that the created relations were physically present, externally observed, causally real, semantically true, or durably learned.

HC transfer:

`GENERATED_REASONING_GRAPH != OBSERVED_RELATION_GRAPH`

`ACTIVE_COMPUTATIONAL_EDGE != WORLD_MODEL_FACT`

`TASK_LOCAL_ROUTE != PLASTICITY_COMMIT`

`FLOW_SCORE != EPISTEMIC_CONFIDENCE`

`FLOW_SCORE != AUTHORITY`

## OBSERVED configured-density state versus ephemeral topology

`DeltaGNN` stores a `density` field. The training code can call `model.update_density(...)` every 50 epochs when a separate flow-control option is enabled, lowering density toward a floor.

That persistent model configuration is distinct from the per-call/per-layer adjacency objects generated by `filter_edges`.

The source therefore supplies a useful three-way distinction:

1. supplied/base graph;
2. configured control parameter governing future filtering;
3. ephemeral effective graph produced during a particular computation.

HC generalization:

`BASE_OR_ELIGIBLE_TOPOLOGY != CONFIGURED_FLOW_POLICY != TEMPORAL_EFFECTIVE_TOPOLOGY`

A configuration-state change may change future effective topology without itself adding/removing a durable logical edge. A transient effective edge/filter result may influence plasticity evidence without becoming a plasticity commit.

## Temporal scope and provenance

A state-dependent effective graph should be interpreted with the scope of the computation that produced it.

Material metadata may include:

- parent topology/reference;
- task/coalition/execution identity;
- producing transform or filter;
- score source and version;
- state snapshot used by the filter;
- onset/layer/phase;
- expiry/dissolution;
- retained/suppressed/generated relations;
- whether relations are computational-only, evidence-bearing, or durability candidates;
- plasticity eligibility;
- provenance.

This need not imply that every internal micro-edge becomes a durable audit record. The required observability is consequence- and qualification-dependent.

## Plasticity boundary

Repeated selection of one route can provide evidence for learning, but the current effective topology is not itself durable learned topology.

`ROUTE_USED_NOW != ROUTE_LEARNED_FOR_FUTURE`

`REPEATED_EFFECTIVE_EDGE != AUTOMATIC_DURABLE_EDGE`

`FORWARD_FILTER_RESULT != PLASTICITY_UPDATE`

A transition from task-local effective routing into durable logical eligibility, learned weight, gate, or hyperedge membership must cross the ordinary HC plasticity/admission boundary with provenance and state-class semantics.

## Salience/epistemic/authority boundary

A node or edge can receive a high flow score because it is useful for a current computational objective. That score is not automatically:

- evidence strength;
- causal importance in the external world;
- salience outside the declared task;
- moral/value priority;
- consent;
- action authority;
- protected-update authority.

This reinforces the existing HC separation between routing influence, epistemic support, salience, and governance.

## OBSERVED source-code cardinality anomaly

Static inspection of `generate_heterophily_graph` finds a cardinality mismatch in how self-loop pairs and edge values are constructed.

The function appends self-loop index pairs for every node in `G.nodes`, but the count of appended scalar edge values uses `len(selected_nodes)` rather than `len(G.nodes)`:

```text
edge_index_list.extend([(node, node) for node in list(G.nodes)])
edge_attr_list.extend([1] * (len(edge_pairs) * 2 + len(selected_nodes)))
```

For any connected component containing more than one node, the number of index pairs added for self loops exceeds the self-loop value count implied by `len(selected_nodes)`. Thus the inspected code constructs row/column and value sequences with unequal cardinality in that case before passing them to the sparse-tensor constructor.

Status: OBSERVED STATIC IMPLEMENTATION ANOMALY.

The runtime effect, reachable dataset cases, library error behavior, and publication-level impact are UNKNOWN here. Do not promote this source anomaly into an HC requirement beyond the already-general rule that generated topology objects require structural-integrity checks before use.

## Adversarial tests suggested

1. Hold base topology fixed while changing activation-derived flow scores; require effective topology to change without mutating structural/logical topology.
2. Produce a transient generated edge during one coalition and dissolve the coalition; require that edge not persist unless admitted through plasticity.
3. Force high flow score onto a low-reliability proposition; verify score does not increase epistemic confidence by itself.
4. Force high flow score on an unauthorized action path; verify it does not create effect authority.
5. Repeatedly select one transient route; verify frequency alone does not silently create protected preference, identity, or durable route.
6. Change configured density/policy while holding the base graph fixed; verify this is represented as configuration-state change rather than physical topology mutation.
7. Generate computational links absent from observations; verify they remain computational relations unless independently admitted as world-model evidence.
8. Inject a generated topology object with mismatched edge-index/value cardinality; require integrity validation before activation.
9. Replay the same input/state snapshot with deterministic routing and verify the same effective topology or explicitly record nondeterministic factors.
10. Observe test metrics repeatedly without using them for adaptation; require exposure lineage to record visibility while avoiding an unsupported claim that parameter training occurred.
