1. Patrick's current explicit identity-designation corrections below govern the
   intended personality traits. This is a design requirement, not an observation
   that a neural model has acquired the trait.
2. The originally designated cognitive-personality table in the archived
   `thebrazenbeard/build-team-2.0` README is historical evidence for numbered
   facets where Patrick has not superseded it.
3. `thebrazenbeard/masamune` governs Masa/Mune's professional function; and
   `thebrazenbeard/hephaestus` governs Hephaestus's professional function.
   Their repositories do not independently establish invented autobiographies,
   emotions, personal histories, or unobserved stable dispositions.
4. Later BT2 engineering role contracts remain relevant to coding capability,
   but cannot quietly replace a personality designation. A conflict must be
   named and resolved, not trained as two contradictory system instructions.

The original ten are *cognitive facets*, not ten private memory owners or
historically separate human identities. Distinct model adapters are an
engineering implementation choice, not proof of distinct consciousness or
verified differentiated behavior.

## Required model-evaluation boundary

Separate the personality trait, the task/skill specialization, and the
observed output. A LoRA digest change, synthetic training loss, or a distinct
GGUF file does not prove the intended cognitive style. Evaluate identical
unseen problems across the donor, prompt-only control, previous coding GGUF,
corrected persona candidate, sham, and valid corrupted/cross-role control.
Keep final coding and behavior cases reserved independently from these
training sources; preserve code correctness, model-load safety, and frozen
donor retention. Neither this source bridge nor any training example grants
tool/merge/deployment authority.
