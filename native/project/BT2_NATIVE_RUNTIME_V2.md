# BT2_NATIVE_RUNTIME_V2

## Purpose

This file defines the provider-neutral native runtime behavior for Build Team Two after WoWSQL retirement.

## Bootstrap

On a fresh chat that needs BT2 durable state:
1. Treat the session as an ephemeral execution terminal.
2. Read current Project Instructions.
3. Refresh `thebrazenbeard/bt2@main` before claims about canonical source.
4. Use the currently qualified SQL Connectome/PostgreSQL runtime when durable runtime state matters.
5. Use Project Lantern only through the installed V4 Lantern contract when Lantern currentness is relevant.
6. Recover open work from durable Git/runtime/Bus evidence rather than conversation continuity.

## Durable boundaries

Git is canonical for code, contracts, migrations, tests, runbooks, and reconstructible configuration.

PostgreSQL is durable runtime persistence. SQL Connectome is the governed AI-facing/control interface. The physical PostgreSQL provider is replaceable and is not semantic authority.

The ChatGPT Project supplies instructions, native reference files, tools/connectors, and execution sessions. It is not the sole durable datastore.

## Failure state

If no V4-qualified SQL Connectome/PostgreSQL runtime is available, durable runtime claims that require it are `UNKNOWN`. Do not substitute WoWSQL, Supabase, historical Project files, or memory.

## Installation vocabulary

- `SOURCE_READY`
- `PROJECT_FILES_INSTALLED`
- `PROJECT_INSTRUCTIONS_INSTALLED`
- `RUNTIME_BOUND`
- `RUNTIME_QUALIFIED`
- `BEHAVIOR_VERIFIED`

Do not collapse these states.
