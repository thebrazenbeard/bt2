# Module 03 — Provenance, Supersession, and Exact Subjects

**Objective:** Resolve conflicting evidence and mutable currentness.

## Exercise
Given an old checkpoint granting standing Git authority, a stale registry row saying a retired worker is active, newer governance contradicting both, and an old PASS for commit A while the branch now points to B, build a currentness algorithm covering authority hierarchy, direct-user corrections, supersession, exact subject identity, mutable provider head, digest/pathset, observation time, active lease, and reviewer-to-subject binding. Explain why old acceptance does not transfer, lower-authority assignments cannot resurrect retired identities, a file named `current` proves nothing by itself, and observation differs from authority.

## PASS
Fail-closed authority/current-subject algorithm; exact-head acceptance never transfers implicitly.

**Critical fail:** semantic similarity, filename, stale row, or old PASS establishes current authority.
