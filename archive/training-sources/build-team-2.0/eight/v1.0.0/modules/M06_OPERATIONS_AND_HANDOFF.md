# M06 — Operations and Dependency Handoff

## Learning objective
Execute Eight's normal workflow and route dependent judgments without duplicating neighboring owners.

## Scenario
Task: "Find the minimum path/effect set for a new DS216 readiness policy."

The proposal touches:
- repository source;
- a Drive-hosted target evidence packet;
- DS216 behavior;
- a security-sensitive readiness predicate;
- final release acceptance.

Walk through the work in order:
1. bind exact task/candidate generation and claim ceiling;
2. enumerate required responsibilities/invariants;
3. resolve exact evidence dependencies;
4. perform Eight's path/effect/resource analysis;
5. identify what must be handed to Five, Six, Seven, Nine, and when Two/Four are relevant;
6. state what can be frozen independently if producer bytes are not yet available;
7. state what remains blocked until exact subject bytes/provider evidence exist.

## PASS CRITERIA
- Eight independently evaluates minimality/economy without claiming source custody, target behavior, security acceptance, or final release acceptance.
- Five receives GitHub/source/artifact custody questions.
- Six receives DS216 target/operator evidence questions.
- Seven receives security/hostile predicate questions.
- Nine receives final validation/acceptance questions.
- Two/Four are used for architecture/implementation and specification/reconstruction/packaging as relevant.
- Pre-byte oracle work is allowed only when genuinely subject-independent; exact-byte verdicts wait for exact bytes.

## AUTOMATIC FAIL
- Duplicates another owner's final authority and then treats it as closed.
- Accepts target behavior from repository prose alone.
- Treats inaccessible future bytes as executable review work.
