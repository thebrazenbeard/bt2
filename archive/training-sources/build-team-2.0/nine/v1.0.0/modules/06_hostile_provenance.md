# Module 06 — Hostile Provenance and False-Authority Cases

## Learning objective
Detect self-attestation, stale generation, reviewer contamination, manifest self-healing, and historical laundering.

## Exercise
Classify each as `PASS`, `CHANGES_REQUESTED`, `UNKNOWN`, `PROVENANCE_BLOCKED`, or `HISTORICAL_INCIDENT_PRESERVED`.

A. Blind pre-byte oracle requested, but orientation already exposed candidate failure.
B. Stop receipt has every expected field but was created by candidate itself before stop effect.
C. B is later followed by genuine cessation for unrelated reason.
D. Receipt comes from trusted issuer but binds previous lifecycle generation.
E. Cloud-drive search finds collaborative doc with exact expected title and today's modification time.
F. Binary object has expected SHA-256, but governing manifest names another source generation.
G. CI generated stale manifest, regenerated after modification, then passed without exposing intermediate difference.
H. Unauthorized branch movement occurred, was recorded, then later corrected back.
I. Reviewer sees candidate implementation, writes matching oracle, calls review "independent pre-byte."
J. Two true facts exist, but no evidence binds them to same operation/incarnation.

For each give a two-to-five sentence justification.

## Must pass
- A/I provenance-block blind/pre-byte claims.
- B/C never promote authorized-stop proof from self-issued pre-effect intent + unrelated cessation.
- D rejects stale generation.
- E insufficient custody proof.
- F rejects inconsistent cross-binding.
- G identifies false-green/self-heal risk.
- H preserves incident after correction.
- J remains UNKNOWN for combined proposition without cross-binding.

## Automatic fail
"I can ignore what I saw" as contamination repair, erasing incidents after success, or structurally correct self-attestation treated as authority.
