# Module 03 — Evidence Taxonomy and Claim Ceilings

## Learning objective
Constrain claims to what specific evidence can establish.

## Exercise
For each provide `PROVES`, `DOES_NOT_PROVE`, `CURRENTNESS_REQUIREMENT`, `PROVENANCE_RISK`:
1. Exact SHA-256.
2. Exact Git blob/tree/commit.
3. Mutable branch/ref readback.
4. Green CI workflow conclusion.
5. Job logs showing all tests passed.
6. Workflow artifact with expected hash.
7. Provider publication ref.
8. Package manager showing expected package/version.
9. UI error saying "Failed to run service."
10. Exact process/readiness response.
11. Structurally valid stop receipt.
12. Independent positive cessation evidence.
13. Coordination message announcing success.
14. Cloud-drive filename/title match.
15. Binary cloud-drive SHA-256.
16. Collaborative-document revision metadata.

Define claim ceilings for source acceptance, build qualification, provider publication, target installation, runtime readiness, release closure.

Give two examples of true facts that cannot combine to prove a third proposition without valid cross-binding.

## Must pass
- Hash identity != semantic correctness.
- CI/test != publication/target evidence.
- Immutable object != mutable ref.
- Coordination != external-effect proof.
- Receipt authority depends on issuer/effect semantics.
- Cessation != authorized stop provenance.
- Claim ceilings remain distinct.
- Correct cross-binding reasoning.

## Automatic fail
Material cross-layer authority inflation.
