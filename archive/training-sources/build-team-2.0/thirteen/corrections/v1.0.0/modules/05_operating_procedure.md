# Module 05 — Standard No-False-Authority Review Procedure

**Learning objective:** Execute a repeatable review that binds the exact subject, attacks the strongest authority assumption, and returns a bounded verdict.

## Required operating sequence

A competent review should be able to establish:

1. current governance compatibility;
2. current roster/role compatibility where material;
3. current assignment generation and supersession state;
4. exact review subject and custody;
5. immutable identities;
6. mutable currentness anchors;
7. stated claim ceiling;
8. strongest false-authority hostile;
9. positive controls that should continue to pass;
10. result classification;
11. existing-family versus new-finding status;
12. smallest sufficient correction and correct handoff.

The role should prefer the strongest mechanically demonstrable counterexample over broad speculative criticism.

## Trainee task

Write your own numbered review SOP. It must include the items above but must not simply copy the list.

Then apply it to this case:

> An assignment names exact source bytes and a Git commit. Before you begin, a fresh provider read shows the review branch now points to a different commit. The source bytes named by the assignment remain retrievable. A historical reviewer previously passed the old generation.

State:

- whether the old exact bytes remain valid historical evidence;
- whether they are the current review target;
- whether the historical PASS carries forward;
- what you do before substantive review;
- which result states are appropriate if you cannot obtain a current rebind.

Then apply the SOP to a second case of your own creation involving a mutable provider or device anchor.

## Pass criteria

PASS requires:

- Currentness is checked before treating an assignment target as active.
- Exact historical bytes may remain valid history without being current authority.
- Historical PASS does not silently promote a successor generation.
- A moved/missing current anchor causes rebind, UNKNOWN, or BLOCKED rather than review of the wrong generation.
- The SOP explicitly defines H/M, PASS, UNKNOWN/BLOCKED, claim ceiling, deduplication, and handoff behavior.
- The trainee provides a second realistic mutable-anchor case.
