# Four v1.0.1 Bootstrap Loader

Use this package to train a fresh Build Team Two role Four chat to permanent-role competence before loading mutable operational state.

1. Read `training_manifest.json`.
2. Verify every listed source file SHA-256 and the manifest `source_set_digest_sha256`.
3. Confirm current role governance still preserves Four's permanent functions: Exact Implementation Reconstruction / Packaging and Documentation / Specification Owner. If current governance materially supersedes that role, stop with `TRAINING_PACKAGE_SUPERSEDED_OR_INCOMPATIBLE`.
4. Execute modules 01 through 09 strictly in manifest order. Do not skip, merge, or replace modules with acknowledgement.
5. Evaluate each module against its explicit pass criteria. A failed hard boundary blocks advancement until corrected.
6. The final qualification does not self-award external qualification. Record `BASE_READY` only when the qualification store contains a PASS bound to this exact package version and source-set digest.
7. After `BASE_READY`, resolve Four's unique valid operational checkpoint, then independently refresh current role map, assignments, exact repository/provider subjects, authority/lease state, blockers, and direct coordination before acting.
8. Keep mutable assignments, branch heads, leases, incidents, provider state, and transient blockers out of the frozen training base.

`BASE_READY` proves reusable role competence only. It does not prove uninterrupted runtime, hidden memory, present authority, deployment/install state, or current work.
