# Metacognitive Monitoring

Status: canonical focused cognition contract.

## Purpose

Metacognition monitors and reasons about the HC's own cognitive processes: confidence, uncertainty, strategy quality, knowledge gaps, resource use, error patterns, and when to seek additional evidence or change approach.

It is **not** a second little mind watching the first and is not a universal executive.

`METACOGNITIVE_MONITOR != HOMUNCULUS`

## Core capabilities

Metacognitive processes may:

- estimate confidence and uncertainty;
- detect unresolved conflict;
- identify missing knowledge or capability;
- monitor strategy performance;
- detect repeated error, oscillation, or loop behavior;
- recommend broader coalition recruitment;
- recommend external evidence/tool use where useful;
- distinguish observed result from inferred explanation;
- track whether predictions/interventions discriminated rival hypotheses;
- initiate bounded review/recovery proposals;
- detect stale evidence or stale model state;
- recognize when current resource expenditure is no longer justified.

These are monitoring and proposal functions. They do not create truth, memory currentness, or action authority by themselves.

## Confidence discipline

Confidence should be grounded in evidence/model state rather than prose fluency, repetition, salience, social approval, or local model certainty alone.

Where confidence is itself uncertain, the HC should be able to represent that uncertainty.

## Strategy monitoring

A metacognitive trace may carry:

- task/context;
- strategy attempted;
- assumptions;
- evidence obtained;
- outcome;
- residual uncertainty;
- error class;
- resource cost;
- recommendation such as continue, expand, revise, stop, seek evidence, or escalate.

A recommendation is not a binding command unless a separately authorized control contract says so.

## External evidence and tool use

Metacognition may determine that external compute, search, retrieval, measurement, or specialist processing would improve the task.

That recommendation routes through the appropriate HC-owned interface. External results return as typed evidence/service outputs and do not become task ownership, belief authority, or self-state merely because metacognition requested them.

## Error awareness

The HC should be able to represent operational states such as:

```text
I_DO_NOT_KNOW
I_AM_UNCERTAIN
MY_CURRENT_MODEL_CONFLICTS
MY_LAST_ACTION_FAILED
MY_EVIDENCE_IS_STALE
MY_STRATEGY_IS_NOT_WORKING
MY_RESOURCE_BUDGET_IS_EXHAUSTED
MY_CONFIDENCE_ESTIMATE_IS_UNRELIABLE
```

These states should remain usable downstream rather than being hidden solely to satisfy an output format.

## Interaction with salience and arbitration

Metacognition may raise salience or request arbitration when conflict or repeated failure warrants broader attention. It does not automatically outrank the evidence, goals, authority gates, or other subsystem state it monitors.

A metacognitive loop must itself be bounded so self-analysis cannot starve the primary task or become a permanent high-priority coalition.

## Learning interaction

Repeated metacognitive evidence may propose strategy/plasticity updates, such as changing route preference or uncertainty calibration. Durable changes remain subject to plasticity admission and protected-invariant checks.

`SELF_CRITIQUE != AUTOMATIC_SELF_MODIFICATION`

## Failure modes

- confidence inferred from eloquence;
- endless self-analysis starving the primary task;
- metacognitive monitor becoming a universal executive;
- uncertainty hidden for output convenience;
- repeated failure rationalized instead of triggering strategy review;
- self-critique automatically trusted without task evidence;
- metacognitive recommendation bypassing action/effect authorization;
- external-tool success causing future external outputs to bypass internal adjudication.
